# Mimir 浏览历史档案

长期保存 HTTP/HTTPS 浏览历史，按日期、标题、网址和域名查找；提供本地统计、按需 AI 分析，以及 GitHub 私有仓库备份。

## 安装

1. 在 Edge 地址栏打开 `edge://extensions/`。
2. 开启“开发人员模式”，点击“加载解压缩的扩展”。
3. 选择本项目目录，也就是包含 `manifest.json` 的文件夹。
4. 在工具栏的扩展菜单中，将 Mimir 显示到工具栏。

首次安装会自动补录浏览器目前仍保留的历史，记录较多时需要一些时间。弹窗和设置页可查看进度；关闭弹窗不会停止后台任务。

请保持扩展目录位置固定。以后升级应在同一目录更新文件，再到扩展管理页面点击“重新加载”，不要先移除扩展。更换目录或电脑前，先导出历史或确认 GitHub 备份已完成。

## 日常使用

- 平时无需操作：访问时自动保存，每小时补录一次。
- 点击工具栏 Mimir →“打开档案”，按日期、关键词或完整域名查找。
- “全部历史”包括浏览器已不再保留、但 Mimir 曾保存的记录。
- “立即同步”会补录、去重，并在已配置 GitHub 时上传待备份记录。采集暂停时，此按钮只备份已保存的数据。
- “统计与 AI”查看所选范围的访问次数、独立网址、网站排行和活跃时段。访问次数不代表停留时长。

## 导入已有历史

打开“设置与备份”底部的“本地导出与导入”：

- 旧版 Mimir JSON：点击“选择文件导入”，选择包含 `history` 数组的 JSON。
- 新版单独分片：选择一个或多个 `.jsonl.gz` 文件。
- 完整导出：点击“选择导出文件夹”，选择包含 `archive-index.json` 和压缩分片的文件夹。

重复导入不会增加重复记录。完成后会显示读取、新增、重复、更新旧版记录和无效条数。旧版只记录最近访问的页面，会标为“旧版记录”；不会把当时的累计访问次数变成虚构日志。

## 配置 GitHub 自动备份

1. 在 GitHub 创建一个专用 **私有仓库**，创建时勾选添加 README，让仓库有默认分支。
2. 在 GitHub 的 Settings → Developer settings → Personal access tokens → Fine-grained tokens 创建令牌。
3. Repository access 只选择这个仓库；Repository permissions 中给 Contents **Read and write** 权限。
4. 在 Mimir 设置页填写仓库所有者、仓库名和令牌。分支可留空，保存时会读取默认分支。
5. 勾选“每日自动备份”，点击“保存设置”。保存时验证仓库和分支；首次写入时确认令牌的实际写权限。
6. 点击“立即同步”。以“最后完成上传”更新为本次时间作为整轮备份成功的依据。

备份是普通压缩档案，拥有私有仓库访问权的人可读取网址、标题和时间。API Key 和 GitHub 令牌不会写入档案。

每天自动备份；浏览器关闭、休眠或断网期间错过的任务会在后续运行时补做。首次备份分批上传，不保证在某个固定时刻结束。网络问题和限流会重试，令牌过期或权限问题会直接显示错误。

恢复时，在新安装中配置同一个仓库和分支，点击“从 GitHub 恢复”。记录经过校验后合并到本地，不删除本地已有记录。第一版不做多设备自动双向同步。

## 配置 AI

在设置页填写兼容 Chat Completions 的完整接口地址、准确模型名称和 API Key，保存并允许访问该服务地址。

在档案页选好时间范围，打开“统计与 AI”：

- 问题留空：生成时间段总结。
- 输入问题：根据这段历史回答，例如“最近一个月我主要在学习什么？”
- 可取消请求，也可将结果导出为文本。

仅在点击分析时调用服务，发送汇总统计和最多 180 条按日期与域名选取的标题样本，不自动上传全部历史或完整网址参数。模型使用你填写的名称，不自动切换。较长时间范围会压缩时间线，分析不能代表未包含的样本。

## 独立本地副本

在设置页点击“导出全部历史”，选择一个电脑文件夹。导出完成后，将整个生成的 Mimir 文件夹复制到备份盘或网盘。

请等到页面显示“导出完成”。中断时已写好的分片仍然保留，清单会标明未完成；这些分片可以通过“选择文件导入”分别恢复。密钥和服务配置不包含在导出中。

## 保存范围

Mimir 不主动清理已保存的历史，不采集网页正文、截图、Cookie 或无痕浏览。浏览器已经删除、Mimir 也从未保存的记录无法找回；旧页面当时的标题也不一定能重建。

本地数据属于当前浏览器配置和扩展身份。卸载扩展、丢失浏览器配置或换目录后，需要依靠独立备份恢复。

## 开发与测试

插件无需构建，直接加载项目目录。运行自动化测试：

```sh
npm ci
npm test
```

`fake-indexeddb` 仅为测试依赖，运行时使用随项目提供的 `idb`。真实 Edge 验收脚本为 `tests/browser_check.py`，需要 Python Playwright；只在 `.local/acceptance-profile` 的独立浏览器配置中执行。
